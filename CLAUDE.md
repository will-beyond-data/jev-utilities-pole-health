# CLAUDE.md: jev-utilities-pole-health

Open-source portfolio demo for **Beyond Data** (Will Turner's Brisbane AI and data firm): Maincode's
open decision model **Matilda Jev** triages electricity distribution poles from a photo plus the pole's
asset record, and recommends replace / maintain / defer / reinspect, with low-confidence cases routed
to an engineer queue. The goal is a great demo video and content about what Jev-style decision models
can do. It is not a production system.

**Start every session by reading `docs/handoff.md`** (local only, gitignored). It holds the current status,
the decisions already made (do not re-ask them), the research behind them, and the next steps in
order. [docs/spec.md](docs/spec.md) is the build spec and the data contract between the Python
pipeline and the demo page. Keep both current alongside any change that affects them.

## Honesty rules for this demo (non-negotiable)

- Every number shown (accuracy, latency, cost) comes from a recorded run in `runs/`, with the
  backend, hardware and date next to it. Never invent or estimate a number for display.
- Hugging Face Space timings include queueing and GPU attach: never present them as model speed.
- The mock backend exists only so the UI and tests work without a GPU. Never film or publish mock output.
- Matilda Jev returns decisions and probabilities, not locations. The UI must never draw boxes,
  highlights or heatmaps that imply it localised a defect.
- The pairing of photos (India), locations (Toowoomba OSM) and inspection histories (Canada) is
  synthetic, and the UI footer, README and DATA_SOURCES.md say so.

## Commands

```bash
uv sync                                   # add --extra space for the Hugging Face Space backend
uv run pytest -q && uv run ruff check .   # must stay green
uv run polehealth fetch                   # data into data/raw (OSM extract is already committed)
uv run polehealth build-register          # data/register.json (not committed)
uv run polehealth ask --backend space --image PATH [--record-id osm-...]
uv run polehealth eval --backend {http,space,mock} --task all [--limit N]
uv run polehealth demo-data --backend http [--inspect 300]
uv run polehealth cost --gpu-hourly-usd X --run runs/<dir>
uv run polehealth serve --backend http    # demo at http://127.0.0.1:8000 plus "Try a photo"
```

Env: `HF_TOKEN` (Space backend), `MJ_URL` and `MJ_API_KEY` (self-hosted server on the GPU box).

## Layout

- `src/polehealth/questions.py`: the single source of truth for every question, the policy text and
  the routing rule. Prompt wording changes go here and nowhere else.
- `src/polehealth/jev.py`: backends (HTTP to the official Maincode runtime, the HF Space, mock).
- `src/polehealth/{sources,register,evaluate,metrics,demo_data,serve,cli}.py`: data, register,
  evaluation, demo JSON, local server, CLI.
- `demo/`: static page (Leaflet, no build step). `demo/sample/` is mock sample data for UI work;
  `demo/data/` is generated by `polehealth demo-data` from a real run.
- `scripts/gpu/`: `setup.sh` (provider-neutral) and `RUNBOOK.md` (RunPod).
